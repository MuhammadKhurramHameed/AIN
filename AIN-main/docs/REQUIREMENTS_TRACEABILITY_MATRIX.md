## Reading this table honestly

- Every `IMPLEMENTED` row above was exercised live in this session with real requests against real data (not assumed from a UI existing) — where that evidence is a specific number (e.g. "973ms round-trip", "6.8s → 150ms"), that's an actual measurement taken during the work, not an estimate.
- Nothing is `PRODUCTION_READY` yet. MFA, rate limiting, and audit-grade logging (AUTH-003, SEC-002, SEC-003) are now real and verified; the remaining gate is TEST-001 maturing from a starting suite into real E2E/load coverage, plus the pre-existing non-security gaps tracked elsewhere in this matrix (refresh-token rotation, full programme-scoped data isolation, etc.).
- `PROG-001`/`PROG-002` are intentionally split: creating a new programme and giving it its own tracks is real and works today; full cross-collection isolation (a Programme B trainee/report/partner never touching Programme A data) is the natural next increment, not yet done.
